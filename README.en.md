# YukiHub Desktop

The desktop edition of YukiHub, for Windows and Linux — a Galgame / visual novel
library manager, launcher and playtime tracker.

> **Status: usable, not yet released.** The code builds and runs day to day, while the
> UI and behaviour are still being aligned with the Android app
> (see [docs/ROADMAP.md](docs/ROADMAP.md), Chinese). **No official installer has been
> published yet**, and binaries are not code-signed.

## What this is

YukiHub has two ends:

| End | Repository | License |
| --- | --- | --- |
| Android | https://github.com/xm486/YukiHub | GPL-3.0 |
| Desktop (this repository, Windows / Linux) | https://github.com/xm486/YukiHub-for-Desktop | AGPL-3.0 |
| Desktop (hosted on GitCode) | https://gitcode.com/xm486/YukiHub-for-Desktop | AGPL-3.0 |

The desktop edition is hosted on both GitHub and GitCode (a China-based code
hosting platform); both copies are kept in sync.

The desktop edition is not a port of the Android app. Both ends share the same data
semantics and habits: game library, play sessions, metadata scraping, sync and backup.
Data can be imported and exported between the two ends, and cloud sync uses the same
snapshot format (schema 5) — see
[migration design](docs/mobile-yukihub-migration.md) (Chinese).

## Capabilities

- **Library**: manual add, batch directory scan, drag-and-drop import; migration from
  Playnite, PotatoVN, Vnite, ReinaManager, LunaBox and YukiHub backups (`.ykbak`);
  categories, favourites, filters and a BigScreen browsing mode
- **Launching**: Windows process detection and exit monitoring for automatic playtime
  tracking; **bundled** Locale Emulator (Japanese locale) and Magpie (scaler), both
  replaceable with your own copies; save-data backup, system tray, launch at login,
  `yukihub://` URL protocol
- **Metadata scraping**: VNDB, Bangumi (+ mirror), Ymgal, Hikarinagi, NextMoe, Steam,
  TouchGAL, DLsite, ErogameScape — cached locally for offline use
- **YukiHub account**: email sign-up / sign-in / password recovery; quick sign-in with
  NextMoe or Hikarinagi (OAuth authorization code + PKCE over a local loopback callback,
  the client never sees the third-party token); cloud sync and auto backup
- **Social**: friend list (playing / online / offline), direct messages, group chats,
  stickers and image messages, @mentions, user profiles
- **Home**: playtime overview, quick-launch rail, game carousel and a
  **Galgame news** carousel (from NextMoe `/v2/news`)

## Tech stack

| Layer | Stack |
| --- | --- |
| Backend | Go 1.27.1, [Wails](https://v3alpha.wails.io) v3 beta behind a single `internal/wailsruntime` isolation layer, [DuckDB](https://duckdb.org) (prebuilt libs in `lib/`), SQLite for importers, WebView2 |
| Frontend | React 18 + TypeScript, Vite, UnoCSS (with Material Design Icons), Zustand, TanStack Router / Query, i18next (zh-CN / zh-TW / en-US / ja-JP), Chart.js, `@wailsio/runtime` |
| Packaging | NSIS 3.13 (`build/windows/nsis`), frontend bundled via `go:embed frontend/dist`; bundled compat tools ([Locale Emulator](https://github.com/xupefei/Locale-Emulator) 2.5.0.1, LGPL-3.0; [Magpie](https://github.com/Blinue/Magpie) 0.12.1, GPL-3.0) in `build/compat-tools` |
| Services | Metadata sources above; YukiHub account service for friends / chat / sync; NextMoe `api.nextmoe.dev/v2/news` for home news (proxied and cached by the local backend) |

> `frontend/bindings/` is generated by `wails3 generate bindings` — **do not edit by hand**.

## Build from source

Supported platforms: **Windows 10/11** and **Linux (amd64)**. macOS / iOS are not supported.

Requirements:

- Go (version in `go.mod`, currently **1.27.1**)
- A **CGO compiler** — DuckDB needs CGO (MinGW-w64 gcc on Windows, `build-essential` on Linux)
- Node.js **22+** and **pnpm 12** (pinned via `packageManager` in `frontend/package.json`;
  `corepack enable` will fetch it)
- Wails v3 CLI, version **exactly matching** `github.com/wailsapp/wails/v3` in `go.mod`

**Linux (amd64) extras:**

```bash
sudo apt-get install -y build-essential pkg-config desktop-file-utils \
  libayatana-appindicator3-dev libgtk-4-dev libwebkitgtk-6.0-dev
go install github.com/goreleaser/nfpm/v2/cmd/nfpm@latest

# ⚠️ Run the Wails patch before any direct `go build` (tray / WebKitGTK rendering);
#    wails3 dev, the Taskfile and scripts/build.sh already run it for you
./scripts/patch-wails-linux-tray.sh

./scripts/build.sh all <version> amd64   # deb / rpm / AppImage
```

```bash
cd frontend && pnpm install && cd ..
wails3 generate bindings -clean=true -ts
wails3 dev -config ./build/config.yml -port 9245

# Build (⚠️ wails3 build does NOT build the frontend)
pnpm --dir frontend build
wails3 build
```

> **`wails3 build` only compiles Go.** It embeds `frontend/dist` as-is, so if you change
> frontend code and only run `wails3 build`, you get a new exe with the old UI.
> Always: **change frontend → `vite build` → `wails3 build`**.

Before committing:

```bash
gofmt -l .
go vet ./...
go test ./... -count=1
cd frontend && pnpm typecheck && pnpm lint && pnpm i18n:check
```
